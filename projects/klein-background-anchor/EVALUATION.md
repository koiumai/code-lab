# 検証結果と限界

2026-11-13。公開サンプル2例（クマ・人物）、seed42、最大辺768、4steps、NF4 FP16、FP32 VAE、PyTorch allocator上限6.5GiB。Ubuntu24.04のRunPod A40で通常生成と背景拘束生成を同じ初期noiseで比較しました。会社の画像は使用していません。

|例|torch allocated peak|reserved peak|driver sampled peak|通常 / 拘束の秒数|
|---|---:|---:|---:|---:|
|クマ|3.336GiB|4.971GiB|5425MiB|3.106 / 2.881|
|人物|3.907GiB|6.330GiB|6817MiB|3.157 / 3.098|

peakは両方式を実行した同じprocess全体。driverは約0.5秒間隔の計測で瞬間peakを逃す可能性があります。モデルDL・ロード時間は上記生成秒数に含めません。A40でのallocator上限は物理8GB/RTX2080の実測代用ではなく、新しい背景拘束経路のRTX2080成功を保証しません。

物体から32model pixels以上離れた背景の、入力に対するraw RGB平均絶対誤差（8bit）はクマ17.67→3.90、人物19.68→1.31。背景の色・露出の漂いは減りました。ただしこれは調和品質の点数ではありません。VAE再構成と境界の影響が残り、raw背景は完全一致ではありません。最終PNGではmask外をコピーして一致を保証します。

目視では人物は控えめな露出/色変化、クマは胴・脚が暗くなりすぎる傾向がありました。既定blend0.5はこの過剰な変化を抑える出発点です。入力に応じて調整してください。既存の影をbaselineから保持した比較も確認しました。影のない入力と物体maskだけでは接地影を新しく作らないので、これだけで影生成込みの品質が完成したとは考えていません。
